# Workflow คลังและโหลดรถ — Truck-first

## 1. รับสินค้าและจัดเก็บ

หน้า Inbound แนะนำ HU Code อัตโนมัติ พิมพ์แก้เองได้ ระบบตรวจไม่ให้ซ้ำ หลังรับสำเร็จเตรียมรหัสสำหรับรับครั้งต่อไปโดยแยกจาก HU ที่รอ Putaway

จัดเก็บโดยเลือก โซน → Rack → Bay → Level → Position

## 2. นำลง Checkout โดยยังไม่ขายหรือส่ง

จาก Rack Map คลิกช่องสินค้า → ดำเนินการสินค้าจากชั้นนี้ → นำไป Checkout / ตรวจ QC

หรือค้นหาสินค้าแล้วเลือกจากตำแหน่งนั้น สินค้าพักตรวจ QC / ให้ลูกค้าดูตัวอย่างได้โดยไม่มี Shipment เก็บคืนชั้นหรือย้อนสถานีได้ตามสถานะและตำแหน่งที่รองรับ

## 3. เตรียมรถก่อนมีรายการส่ง

หน้ารอบรถขนส่ง → ลงทะเบียนรถมาถึง → เลือกคลัง รถ และคนขับรอบนี้

เลือกช่องโหลดที่วางแผนไว้ได้ หรือเลือกภายหลังเมื่อเข้าช่อง รถเปิดรอบและจอดรอได้โดยไม่มี Shipment สถานะเริ่มต้น WAITING_DOCK ไม่ถือว่ารถพร้อมโหลดจนกว่าจะนำเข้าช่อง

เปิดรอบรถ → เลือกช่องที่ว่าง → นำรถเข้าช่องโหลด → AT_DOCK

ข้อมูลรถ คนขับ และช่องโหลดอยู่ในรอบรถ ไม่กรอกซ้ำทุก Shipment รถหรือคนขับที่มีรอบไม่ปิดไม่สามารถลงทะเบียนซ้ำได้

## 4. สร้างรายการส่งเมื่อซื้อขาย/ส่งจริง

คลิกสินค้า Checkout → สร้างรายการส่งจาก Checkout → เลือกลูกค้าและจำนวน

ไม่ต้องระบุรถในขั้นตอนนี้ ส่งทั้ง HU หรือแยกบางส่วนได้ ส่วนที่เหลือยังอยู่ Checkout และเก็บคืนชั้นได้

ตรวจผ่านแล้วนำสินค้าไป Loadout เมื่อต้องการโหลด ให้เลือก “รถที่จอดรอรับสินค้า” ในหน้า Shipment เพียงตัวเลือกเดียว ตัวเลือกแสดงรถ ทะเบียน คนขับ ช่องโหลด และรอบรถ

แสดงเฉพาะรถ AT_DOCK / LOADING ในคลังเดียวกัน ไม่แสดงรถที่ยังไม่มาถึง รถรอเข้าช่อง รถโหลดครบแล้ว หรือรถที่ออกไปส่ง

## 5. โหลดจากหน้ารอบรถ

อีกทางหนึ่ง เปิดรอบรถ → เลือกรายการส่งที่รออยู่ Loadout → เพิ่มรายการส่งเข้ารถคันนี้

ระบบตรวจว่าทุก HU อยู่ Loadout และจองครบ แล้วผูกรถ/คนขับ/ช่องโหลดจากรอบให้อัตโนมัติ และปรับรายการส่งเป็น READY_TO_LOAD

เริ่มโหลดสินค้าทั้งรอบ → สแกน HU Code ด้วย barcode/พิมพ์แล้ว Enter หรือกดสแกนในแถวรายการ

สแกนได้เฉพาะ HU ที่อยู่ในคิวของรถคันนี้ ไม่สแกนซ้ำและไม่สแกนสินค้าของรถคันอื่น สถานะสินค้าจริงเปลี่ยนจาก Loadout ไปอยู่บนรถเมื่อสแกนสำเร็จเท่านั้น

หนึ่งรถมีหลาย Shipment และหลาย HU ได้ ระหว่าง LOADING ยังเพิ่มรายการส่งที่พร้อมอยู่ Loadout ได้ รายการใหม่เข้าสถานะ LOADING ของรอบเดียวกัน

## 6. ตรวจครบและปล่อยรถ

คิวโหลดแสดง HU และจำนวนที่ขึ้นรถแล้ว ต้องสแกนครบทั้งคันก่อน “ยืนยันโหลดครบทั้งคัน”

หลังยืนยันโหลดครบ (READY_TO_DEPART) ล็อกคิว ไม่เพิ่ม/ถอดรายการแล้ว → ปล่อยรถออกจากคลัง (DEPARTED) → ยืนยันกำลังนำส่ง

รถที่ออกเดินทางไม่อยู่ในตัวเลือกโหลด ช่องโหลดว่างเมื่อรถออกจริง เก็บรายการสินค้า Shipment และ Timeline ต่อรอบรถไว้ดูย้อนหลัง

ชื่อรถเป็นชื่อประจำคัน เช่น “รถขนส่ง 05 (ตัวอย่าง)” ไม่ผูกกับ LOAD/ROAD และไม่เปลี่ยนตามขั้นตอน แยกจากสถานะ “รอโหลด / กำลังนำส่ง” และเลขรอบขนส่ง RUN-… ข้อมูลทะเบียนและคนขับใน demo ระบุว่าเป็นตัวอย่าง ไม่ใช่ทะเบียนจริง

## แก้ไขกรณีเลือกผิดหรือยกเลิก

- เลือกผิดคัน: ถอดรายการออกจากรถก่อนมี HU ของ Shipment นั้นสแกนขึ้นรถ รายการส่งไม่ถูกยกเลิกและยังจองสินค้าไว้ สามารถเลือกเข้ารอบรถอื่นได้
- สแกนขึ้นรถแล้ว: ไม่ให้ถอดรายการด้วยคำสั่งนี้ ต้องดำเนินขั้นตอนขนส่ง/คืนตามสถานะ
- ไม่ส่งแล้ว: ยกเลิก Shipment ทั้งรายการก่อนเริ่มโหลด ปลดจองทุก HU แล้วเก็บคืนชั้นได้ เก็บประวัติ ไม่ลบ Shipment
- ถ้ารายการส่งทั้งหมดถูกยกเลิกแต่รถยังจอดรอ รถยังอยู่ที่ช่องเพื่อรับรายการใหม่ได้
- รถว่างไม่รับสินค้าแล้ว: ยกเลิกรอบรถว่าง หลังถอดรายการส่งออกก่อน ระบบคืนรถและคนขับให้พร้อมใช้งานและปล่อยช่องโหลด
- Return: จัดเก็บ RTN หรือชั้นปกติที่รองรับสินค้าได้ สินค้า RTN ยังเป็นพักรอ ไม่พร้อมเบิกตามปกติ

Dashboard แบบการ์ดและภาพจำลองใช้หน้าคำสั่งสินค้าเดียวกัน แสดงสินค้าตามตำแหน่งจริง รถรวมหลายรายการภายในคันเดียว

## Compatibility และการทดสอบ

รายการและรอบรถเดิมไม่ถูกล้าง ยังคงเปิดรอบรถเดิม ยืนยันมาถึง และเลือกช่องก่อนโหลดได้ API transport แบบเดิมเก็บไว้เพื่อ compatibility แต่ UI ใช้ truck-first workflow

frontend/scripts/verify-truck-first.mjs ใช้เว็บ 5180 และ API ทดสอบแยกที่ 8011 (ตั้ง TRUCK_TEST_API ได้) ต้องเตรียม migration และ seed ในฐานข้อมูลทดสอบก่อน สคริปต์สร้างรอบรถและทำรายการจริงในฐานข้อมูลเป้าหมาย ห้ามชี้ไป production
